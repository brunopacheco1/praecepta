Open source · Apache-2.0 · Java 21+

DMN decision tables for Java, answered in a fraction of a microsecond.

Praecepta (Latin for “rules”, said pry-KEP-ta) evaluates DMN decision tables with strict DMN hit policies. Write tables in a modeller, Excel, CSV or code; validate them when you build; evaluate them with a small engine that has no dependencies, on its own or as beans in Spring Boot, Quarkus or Micronaut.

Benchmarks

  • 0.19 µsper decision on a real 119-rule table
  • 20–2,000×faster than Camunda 8 and Drools, from 10 to 10,000 rules
  • 5 MBof heap for 10,000 rules, against 108–133 MB
  • 76 msfrom a fresh JVM to the first decision, against 379–469 ms

JMH on an Apple M2 Pro, every engine reading the same DMN file and checked to give the same answers. Every log and raw result is published, including where Praecepta 0.1.0 was slower: building large FIRST and PRIORITY tables (#29, fixed in 0.2).

What it does

Strict DMN hit policies

UNIQUE, ANY, PRIORITY, FIRST, OUTPUT ORDER, RULE ORDER, and COLLECT with SUM, MIN, MAX and COUNT.

FEEL cells

Lists, not(...), comparisons, = and !=, intervals and null on string, number, date, boolean, time, date-time and duration columns, with every FEEL literal form (1.2e3, @"2025-01-31", date(2025, 1, 31)), times with an offset or a zone id, and optional input value lists. An input may hold a list, such as nationalities, and in DMN a cell may compare with another input, as in > limit.

Validation when you build

Overlapping rules, conflicting outputs, rules that can never fire, gaps (inputs no rule covers, with an example) and default outputs no input can reach, for list columns too.

DMN in, DMN out

Reads DMN 1.1 to 1.5, including files from Camunda Modeler and outputs that compute, as in (price - discount) * 1.2 or due + duration("P14D"), and writes DMN 1.3 that Camunda and Drools evaluate the same way.

Maven and Gradle plugins

Compile Excel, CSV and DMN tables at build time into typed input and output records, so your application ships only the engine. Both generate the same classes.

Spring Boot, Quarkus, Micronaut

Drop DMN files under rules/ and inject one engine per decision. An invalid table stops the application from starting, or Quarkus from building it, with every problem listed.

Native images

Applications build as GraalVM native executables with no configuration for Praecepta: the engine uses no reflection, and the jars carry the metadata they need.

Small and safe to share

No runtime dependencies, a JPMS module, and immutable engines that any number of threads can share.

Get started

  1. Add the engine

    It has no dependencies. Add praecepta-loader too if you load Excel or CSV files at runtime.

  2. Load a table and evaluate

    Read a DMN file as in the example above, or build the rules in code. Bind each column to a getter of your input, and map the matched outputs to your result.

  3. Or compile tables at build time

    The Maven plugin validates each table, fails the build on errors, and generates typed classes:

    With Gradle, apply the plugin io.github.brunopacheco1.praecepta from the Gradle Plugin Portal (guide).

  4. Or let your framework load them

    Put DMN files under src/main/resources/rules/ and add one module instead of the engine. Each decision becomes an engine bean, named after it; an invalid table stops the application from starting, or Quarkus from building it.

    • Spring Boot 4: praecepta-spring-boot-starter, inject with @Qualifier("Discount") (guide)
    • Quarkus 3.40+: praecepta-quarkus, inject with @Identifier("Discount") (guide)
    • Micronaut 4: praecepta-micronaut, inject with @Named("Discount") (guide)
    • Another framework, or none: praecepta-integration (guide)

The README covers cells, typed columns, DMN support, every plugin option, each integration and native images. The API documentation covers the engine, the loader, the Gradle plugin, the Spring Boot starter, the Micronaut module, the Quarkus extension, and their cores, praecepta-compiler and praecepta-integration.

How it works

Every rule gets one bit. For every column, each value the rules can tell apart gets a mask: the rules that accept it. Numbers and dates are split at the boundaries the rules mention, and a binary search finds the interval.

Evaluating an input looks up one mask per column and ANDs them. A 64-bit AND checks 64 rules at once, and the hit policy reads the result: FIRST is the lowest set bit, a single CPU instruction. Memory grows with columns × values × rules, never with their product, and a mask only a few rules share, such as one product code's, keeps only its non-zero words.

What it is not

Praecepta does one thing: single DMN decision tables, fast. Use Camunda or Drools when you need:

  • Full FEEL: functions, contexts, if and tests that compute, such as income > 2 * rent. Praecepta's input entries are FEEL simple unary tests: in DMN they may compare with another input (> limit) or test a list's elements, but not compute. Output entries may compute with + - * / ** on strings, numbers, dates, times and durations, but call no functions other than the date and time literals.
  • Decision requirement graphs: decisions feeding other decisions, business knowledge models and boxed expressions (#14).
  • A process engine, a modeller or a decision service around the tables.

Secure by design

What you can expect

  • Nothing reaches outside: no network, no processes, no cryptography, no stored data.
  • Untrusted DMN is safe to read: DTDs and external entities are disabled (no XXE).
  • Bad input fails cleanly, with an error naming the decision, rule and column.
  • Declared input values are enforced: anything else is rejected, not matched.
  • Generated code is safe to compile: names and text from tables are sanitised.
  • Releases are authentic: signed, with provenance and an SBOM, and rebuilt bit for bit by an independent project.

Know the limits

  • A table decides what your application does: who may change tables is up to you.
  • A table crafted to defeat validation can still be slow to build (#29): build untrusted tables off the request path.
  • Input size is limited only by the JDK's XML limits: cap uploads yourself.
  • The Spring Boot and Micronaut report endpoints show the rules' conditions: expose them as you would any configuration.

The threat model, trust boundaries and evidence are in the security assurance case. To report a vulnerability, see the security policy.

Open, and easy to check

  • Apache-2.0, and REUSE-compliant: every file states its author and licence.
  • Signed, reproducible releases with an SBOM, SLSA Build Level 2 provenance and third-party notices on every GitHub release; Reproducible Central rebuilds each one and checks it matches Maven Central bit for bit.
  • Checked on every change: tests on Java 21, 25 and 27, an enforced code style, compiler warnings as errors, SonarCloud, CodeQL, dependency checks, and fuzzing of the parsers that read untrusted input.
  • Assessed in the open: every answer behind the Best Practices and Baseline badges links to its evidence, and Scorecard rechecks the repository every week, with what is left to improve.
